# 需求规范：统一工具栏菜单管理

**Feature Branch**: `010-unified-toolbar-menu`

**Created**: 2026-08-14

**Status**: Draft

**Input**: 用户描述: "统一管理所有的工具栏菜单：1.工具栏菜单固定左边为插入空白block和删除，其他的为组件自己的定制化 2.工具栏菜单统一的特性为鼠标悬停出现，离开隐藏 3.工具栏菜单保证全局互斥，严格控制不要出现多个菜单 4.与组件的点击无关，移除相关的工具栏点击事件 5.内嵌组件工具栏展示需要互斥，按照优先级处理"

## 用户场景与测试 *(mandatory)*

### 用户故事 1 - 固定结构与自定制工具栏展示 (Priority: P1)

作为文档编辑用户，当鼠标悬停在任何内容块（Block）上时，我希望看到的工具栏在左侧固定展示“插入空白块”和“删除”通用操作，而在右侧保留该内容块专属的定制化功能，以便获得统一且清晰的操作体验。

**Why this priority**: 统一的布局规则能降低用户的学习成本，并为所有 Block 组件提供标准化的工具栏框架。

**Independent Test**: 鼠标分别悬停在不同类型的 Block（如表格块、图片块、高亮块等）上，校验工具栏最左侧是否固定存在“插入空白块”与“删除”按钮，且右侧正确展示该 Block 独特的定制化功能。

**Acceptance Scenarios**:

1. **Given** 用户在文档中查看任意内容块，**When** 鼠标悬停至该内容块区域，**Then** 出现的工具栏左侧固定包含“插入空白块”和“删除”图标按钮。
2. **Given** 鼠标悬停在特定类型组件（如表格组件或图片组件）上，**When** 工具栏渲染，**Then** 该组件专有的操作选项（如增加行列、图片对齐等）展示在通用按钮的右侧。

---

### 用户故事 2 - 基于鼠标悬停与离开的显隐控制 (Priority: P1)

作为文档编辑用户，我希望工具栏在鼠标悬停时自动显示、鼠标离开后自动隐藏，且该行为纯粹由鼠标悬停驱动，无需点击组件。

**Why this priority**: 悬停显隐能够保持文档界面的整洁干净，避免点击组件触发的交互干扰。

**Independent Test**: 移动鼠标进入与划出 Block 区域，验证工具栏是否即时或按预期平滑显隐，且在非点击状态下也能正常工作。

**Acceptance Scenarios**:

1. **Given** 鼠标移动到某个 Block 区域内，**When** 鼠标进入，**Then** 该 Block 的工具栏菜单自动显示。
2. **Given** 鼠标从某个 Block 及其工具栏区域移出，**When** 鼠标离开，**Then** 该 Block 的工具栏菜单自动隐藏。
3. **Given** 用户在 Block 内进行单纯点击或选区操作，**When** 未产生悬停状态变更，**Then** 工具栏显隐状态仅由当前悬停状态决定，不依赖或响应点击组件事件。

---

### 用户故事 3 - 全局与嵌套组件工具栏互斥与优先级处理 (Priority: P1)

作为文档编辑用户，我希望在任何时候整个文档中最多只显示一个工具栏菜单；对于内嵌/嵌套组件（例如高亮块内部嵌套表格或图片），工具栏展示必须严格按优先级互斥（优先展示最具体的子组件工具栏），绝不出现多个菜单同时叠加的情况。

**Why this priority**: 多菜单叠加会导致界面严重遮挡与操作混淆。在嵌套结构中明确优先级（如最内层子组件优先），能确保用户的操作意图精准匹配当前直接悬停的目标。

**Independent Test**: 在包含嵌套关系的组件（例如高亮块内部的表格）中移动鼠标，校验当鼠标悬停在内层表格时仅显示表格工具栏，当鼠标悬停在高亮块非表格区域时仅显示高亮块工具栏，全程无双菜单并存现象。

**Acceptance Scenarios**:

1. **Given** 某个 Block 的工具栏正处于显示状态，**When** 鼠标移动到另一个 Block 触发新工具栏显示，**Then** 原先显示的工具栏立即被关闭或隐藏。
2. **Given** 存在嵌套组件结构（如高亮容器内嵌图片/表格），**When** 鼠标悬停在内层子组件上，**Then** 按照优先级优先展示内层子组件的工具栏，同时隐藏外层父容器工具栏。
3. **Given** 鼠标从内层子组件移至外层容器的非子组件空白处，**When** 悬停焦点变更，**Then** 工具栏无缝切换至外层容器工具栏，保持全局仅有单工具栏可见。

---

### 边际情况 (Edge Cases)

- 当鼠标在 Block 边缘或工具栏与 Block 之间的缝隙快速穿过时，系统如何处理显隐逻辑？（应设置合理防抖或防误关延时，保证悬停体验流畅）
- 当 Block 位于编辑器顶部或底部边界时，工具栏如何定位以避免弹出菜单被视口裁切？
- 当深层嵌套结构（多层嵌套）发生快速悬停切换时，优先级判定算法能否在 16ms（一帧）内准确响应并完成旧工具栏清理？

## 需求 *(mandatory)*

### 功能需求

- **FR-001**: 系统必须为所有 Block 组件提供统一管理的工具栏框架容器。
- **FR-002**: 工具栏菜单左侧区域必须固定为“插入空白 Block”和“删除 Block”两个通用操作项。
- **FR-003**: 工具栏菜单必须支持右侧插槽/自定制区域，允许具体 Block 组件注入各自特有的操作项。
- **FR-004**: 工具栏菜单的显隐触发必须完全基于鼠标悬停（Hover）与离开（Leave）事件，移除所有依赖 Block 点击事件来显示工具栏的逻辑。
- **FR-005**: 系统必须实现全局工具栏状态管理，保证在任意时刻全页最多仅存在一个处于可见状态的 Block 工具栏菜单。
- **FR-006**: 系统必须支持嵌套组件（Inner Blocks）工具栏的互斥与优先级判定机制：当悬停发生于内嵌组件时，按 DOM/节点层级优先级（最深/最具体节点优先）决定展示该内嵌组件工具栏，并隐蔽外层容器工具栏。
- **FR-007**: 当悬停焦点转移至新 Block 时，系统必须同步清除或隐藏先前所有 Block 的工具栏显示状态。

### 关键实体

- **ToolbarContainer**: 统一的工具栏容器组件，负责左侧通用按钮组装、右侧自定制插槽渲染以及全局显隐与互斥状态对接。
- **ToolbarManager / StateStore**: 全局工具栏状态控制器，维护当前激活悬停的 Block 路径/优先级树，负责跨 Block 的互斥调度、层级优先级判定与销毁通知。

## 成功标准 *(mandatory)*

### 可衡量结果

- **SC-001**: 100% 的 Block 工具栏菜单均统一遵循“左侧固定通用按钮 + 右侧组件自定制项”的结构。
- **SC-002**: 悬停触发工具栏显示的响应延时不超过 100 毫秒，移出隐藏过渡顺畅无残影。
- **SC-003**: 在各种快速悬停与嵌套层级切换测试中，全局出现多工具栏并发重叠的概率为 0%。
- **SC-004**: 移除组件点击触发逻辑后，在单纯悬停浏览场景下所有工具栏功能均能 100% 正常使用。
- **SC-005**: 在嵌套组件场景下，悬停在子组件时父组件工具栏隐藏率达到 100%。

## 假设条件

- 插入空白 Block 与删除 Block 的行为在所有 Block 类型中逻辑一致（插入新建 Block 并在目标位置插入，删除则移除当前 Block 节点）。
- 工具栏悬停判定包含 Block 主体区域以及工具栏容器自身区域，以防止鼠标移向工具栏时意外触发离开隐藏。
- 嵌套组件的优先级规则默认采取“最内层节点优先（Innermost / Most Specific First）”原则。
