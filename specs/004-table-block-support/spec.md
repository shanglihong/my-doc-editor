# Feature Specification: 表格 Block 增强与扩展功能

**Feature Branch**: `004-table-block-support`

**Created**: 2026-08-13

**Status**: Draft

**Input**: User description: "表格block需要支持 1.添加删除行列 2.单元格内可以内嵌文本块 3.可以合并单元格"

## Clarifications

### Session 2026-08-13

- Q: 当在表格悬浮菜单中增加背景颜色设置功能时，背景颜色的应用范围应当支持哪些维度？ → A: 单元格级别：对当前焦点单元格或框选选区内的单元格设置背景颜色（提供预设调色盘与清除背景色）。
- Q: 当用户在表格单元格内部划选文本时，文本格式工具栏（BubbleToolbar）与表格菜单（TableBubbleMenu）应当如何协调展现，以避免界面上双工具栏重叠或遮挡？ → A: 文本选区优先：在表格内划选文本时显示文本格式工具栏并隐退表格菜单；光标单点定位或无文本选区时显示表格菜单。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 动态添加与删除表格行列 (Priority: P1)

作为文档编辑用户，我希望能够根据数据记录的增减，在已有表格的任意行或列位置动态插入新行、新列，或删除不需要的行列，以便灵活调整表格数据规模与结构。

**Why this priority**: 表格最基础的核心交互是行列维度的动态扩展与裁剪，这是表格功能可用的前提保障。

**Independent Test**: 在文档编辑器中插入一个初始 2x2 表格，分别执行“上方插入行”、“下方插入行”、“左侧插入列”、“右侧插入列”、“删除当前行”、“删除当前列”操作，检查表格行列维度变更是否符合预期且内容无丢失。

**Acceptance Scenarios**:

1. **Given** 用户选定了表格中的某个单元格，**When** 用户点击右键菜单或悬浮工具栏中的“在上方插入行”，**Then** 系统在当前行上方新增一行空白单元格，原表格其他数据顺延。
2. **Given** 用户选定了表格中的某个单元格，**When** 用户点击右键菜单或悬浮工具栏中的“在右侧插入列”，**Then** 系统在当前列右侧新增一列空白单元格，原表格其他数据顺延。
3. **Given** 用户选定了目标行/列中的单元格，**When** 用户触发“删除行”或“删除列”操作，**Then** 选中的整行/整列被从表格中移除，相邻单元格无缝拼接。

---

### User Story 2 - 单元格内嵌套与编辑全量块结构 (Priority: P2)

作为文档编辑用户，我希望可以在表格的每个单元格内插入与编辑各类块级结构（如段落、标题、列表、代码块、高亮块、嵌套表格等），以便在表格单元格中组织丰富的文档内容。

**Why this priority**: 单元格内嵌全量块结构赋予单元格完整的微型文档编辑能力，极大提升表格对于复杂知识整理与排版的能力。

**Independent Test**: 在表格单元格中尝试创建代码块或高亮块，验证单元格内部能够正确渲染并独立编辑这些高级块级元素。

**Acceptance Scenarios**:

1. **Given** 光标定位在某个单元格内部，**When** 用户通过快捷指令（如斜杠菜单 `/`）插入代码块或高亮块，**Then** 该块级元素成功内嵌在当前单元格内部。
2. **Given** 单元格内部包含多种类型的块结构，**When** 用户对其中某个块进行编辑或格式修饰，**Then** 操作仅作用于当前块，不影响单元格内其他块或表格外部其他区域。

---

### User Story 3 - 矩形区域单元格合并与拆分 (Priority: P3)

作为文档编辑用户，我希望能够选中跨越多行或多列的矩形单元格区域并将其合并为一个大单元格，以及在需要时将合并的单元格恢复拆分，以便呈现表头分组或复杂多级数据对比。

**Why this priority**: 单元格合并是高级表格排版（如表头跨列、多级汇总）的必要功能，在行列调整与文本块内嵌之后提供更高级的样式组织能力。

**Independent Test**: 框选 2x2 区域单元格，触发“合并单元格”指令，验证选区合并为一个包含跨行跨列的单元格；选中已合并单元格触发“拆分单元格”指令，验证恢复为原始网格结构。

**Acceptance Scenarios**:

1. **Given** 用户通过拖拽框选了 2 个或以上相邻的矩形单元格，**When** 用户点击“合并单元格”快捷菜单，**Then** 所选单元格融合为一个单元格，合并后继承选区左上角及后续单元格的内容。
2. **Given** 光标定位在一个已合并的跨行跨列单元格上，**When** 用户点击“拆分单元格”，**Then** 该单元格被重新划分为原始的单格网格形态，且内容保留在左上角单元格中。

---

### Edge Cases

- 当表格仅剩 1 行或 1 列时，用户执行“删除行”或“删除列”的处理逻辑：不允许删除最后一行或最后一列（系统禁用该按钮或提示“不可删除唯一行列”）。
- 当合并多个均含有复杂块的单元格时，原各单元格内的块结构按从左到右、从上到下的顺序拼接合并到新的大单元格中。
- 当删除的行或列恰好穿过某个合并单元格时，系统需自动修正该合并单元格的跨行（rowspan）或跨列（colspan）数值，防止网格塌陷。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持在表格中指定单元格的上方或下方插入新的数据行。
- **FR-002**: 系统必须支持在表格中指定单元格的左侧或右侧插入新的数据列。
- **FR-003**: 系统必须支持删除表格中选中的数据行（非最后一行）。
- **FR-004**: 系统必须支持删除表格中选中的数据列（非最后一列）。
- **FR-005**: 系统必须支持在单元格内部内嵌与编辑全量块级结构（包括基础文本块、代码块、高亮块、嵌套表格及图表等所有标准 Block 元素），使单元格具备完整的微型文档编辑能力。
- **FR-006**: 系统必须支持用户框选连续的矩形单元格区域并执行合并单元格操作。
- **FR-007**: 系统必须支持对已合并的单元格执行拆分恢复操作，拆分后所有原内容完整保留在左上角首个单元格中，其余恢复出来的子单元格初始化为空白状态。
- **FR-008**: 系统必须在进行行列插入、删除及单元格合并拆分时，自动维护整体表格矩阵（rowspan / colspan）的完整性与对齐。
- **FR-009**: 系统必须在表格悬浮菜单（TableBubbleMenu）中提供单元格背景颜色设置功能，支持对当前焦点单元格或框选选区内的单元格设置与清除背景颜色（`backgroundColor`）。
- **FR-010**: 系统必须支持表格菜单（TableBubbleMenu）与文本工具栏（BubbleToolbar）的互斥展示策略，当单元格内部存在非空文本选区时优先展示文本工具栏并隐退表格菜单，当无文本选区时展示表格菜单。

### Key Entities

- **Table Block**: 表格块总体实体，包含表格的整体行列配置、单元格矩阵数据及跨行跨列属性。
- **Table Row**: 表格行实体，管理行高及该行所持有的单元格集合。
- **Table Cell**: 单元格实体，包含坐标信息（row, col）、跨行数（rowspan）、跨列数（colspan）、背景颜色（backgroundColor）以及单元格内部的块列表（支持全量 Block 嵌套）。
- **Block Content (Cell Internal)**: 单元格内部块实体，承载单元格内的文本段落、代码块、高亮块或嵌套子表格等完整 Block 树。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能在 2 次交互点击内完成任意单元格位置的行列插入或删除操作。
- **SC-002**: 单元格内嵌套各类块元素的编辑交互顺畅，输入响应延迟小于 50ms。
- **SC-003**: 用户框选矩形区域后，合并或拆分单元格操作在 100ms 内完成渲染更新。
- **SC-004**: 复杂表格（包含合并单元格与嵌套高级块元素）在加载、保存与导出过程中，结构与内容正确率达到 100%。

## Assumptions

- 不允许删除表格的唯一最后一行或最后一列（若删除最后一行/列，等同于删除整个表格 Block）。
- 单元格合并仅支持连续的矩形选区，不支持非连续或 L 型选区合并。
- 单元格默认宽度与高度适应内容，并支持通过拖拽表格分割线手动调整行列尺寸。
